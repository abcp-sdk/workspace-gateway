# workspace-gateway

A Go service that fronts the abc agent for the **workspace webui**. It is the
**single trusted entry point for creating sessions** and owns the workspace
model: a tenant sees only the org/repo it maintains, a session is named
`org:repo:branch`, and a session's **preset (tool whitelist) is decided at
creation and is then immutable**.

The webui speaks ONLY `workspace.v1`; the gateway forwards a minimal, policy-free
agent surface and owns session creation + the sandbox lifecycle.

## Why a gateway

The agent lets any authenticated client call `CreateSession` with an arbitrary
`preset`, and `UpdateSettings`/`UpsertPreset` can change it. That means a client
could grant itself any tool whitelist. The gateway closes that hole:

- It is the **only** caller of `CreateSession` that is trusted; the proxied
  `agent.v1.CreateSession`, `UpdateSettings(preset)`, `UpsertPreset` and
  `DeletePreset` are **refused**.
- It derives the role from the session name and binds the immutable preset.
- It filters visibility to the tenant's own repos.

## Roles (immutable presets)

| Role | Session | Tools |
|---|---|---|
| `admin` | — | create org/repo + repo read. No sandbox, no writes |
| `maintainer` | `org:repo:main` | read, review/merge MRs, create branches, sandbox. **No git writes, no sandbox-port** |
| `developer` | `org:repo:<other>` | write its branch + sandbox-port, propose MRs, sandbox. No merge |
| `planner` | free | read all visible repos + sandbox. No git write |
| `explorer` | free | read all visible repos only |

**The `main` branch changes ONLY by merging an MR.** A maintainer has no tool
that writes to main; branch protection (`apply_to_admins: true`, no direct
push) is the enforcement backstop, so even the shared Forgejo token cannot push
to main.

Presets are deployment-seeded via `SYSTEM_PRESETS_FILE` (generated by
`cmd/gen-presets`), which the agent marks `is_system` and refuses to
overwrite/delete.

## RPC surface

The gateway exposes **only `workspace.v1.WorkspaceService`** — the webui never
speaks `agent.v1` directly. The `agent.v1` handler is deliberately NOT mounted.

- **Workspace/session**: `CreateWorkspace`, `ForkWorkspace`, `ListWorkspaces`,
  `GetWorkspace`, `DeleteWorkspace`, `CreateFreeSession`.
- **Git browse**: `ListRepos`, `Tree`, `ReadBlob`, `Log`, `Branches`,
  `EnsureRepo`, `ListMRs`, `CreateMR`, `CommentMR`, `MergeMR`.
- **Sandboxes**: `ListSandboxes`, `CreateSandbox`, `GetSandbox`,
  `DeleteSandbox`, `ResolveSandbox`. A sandbox may be launched from **ANY base
  image**: the gateway derives a runnable image by injecting the agent-worker
  binary into the base at launch time (`FROM <base>` + COPY worker + worker
  entrypoint), pushed content-addressed to `root/sandbox:<hash>`.
- **OCI images**: `ListOCIImages` (browse a namespace; pass `name` to list one
  image's tags), `BuildSandboxImage` (repo Dockerfile -> `<org>/<image>:<tag>`
  via buildkitd).
- **Services**: `DeployService`, `ListServices`, `DeleteService` — run a user
  image as a long-lived Deployment + Service (no worker injection, no sidecar).

Both sandboxes and services take two runtime knobs: `kvm` (request `/dev/kvm`
via the device plugin, non-privileged) and `gpu_count` (NVIDIA GPUs; needs the
GPU device plugin). These are rendered from the deployment's `WORKSPACE_RUNTIME`
settings (device names + KVM security context); `privileged` is never set.

Sandboxes are reclaimed automatically: an idle reaper deletes any sandbox whose
worker reports no jobs (the worker retains a 24h window) once the pod is older
than `SANDBOX_IDLE_TTL` (default 24h). Deleting a session (via the gateway or the
agent's `deleted` lifecycle event) also cascades to that session's sandboxes.
- **Forwarded agent surface** (minimal, policy-free): chat
  (`Prompt`/`WatchSession`/`WatchSessions`/`ListMessages`/`Interrupt`/`Compact`/
  `Undo`/`State`/`Mailbox`), session list/get/delete, `SetModel`, a NARROWED
  `UpdateSettings` (model/variant/locale only), models/providers/config/tools,
  read-only presets (`ListPresets`/`PreviewPreset`), and files.
- **Absent by design**: `CreateSession`, `Rename`, `UpsertPreset`,
  `DeletePreset`, and any policy field (preset/max_turns/system_prompt/group).

Backends: **Forgejo** (git, shared token) and **Kubernetes** (sandboxes). The
gateway owns the sandbox lifecycle in-process (the standalone worker-manager was
folded in under `internal/sandboxmgr`).

## Config

| Env | Meaning |
|---|---|
| `PORT` | listen port (default 8080) |
| `GATEWAY_DB` | sqlite path for the ownership table |
| `AGENT_URL` | agent base URL (h2c) |
| `SANDBOX_NAMESPACE` | namespace the sandbox backend manages (default `worker`) |
| `FORGEJO_URL` / `FORGEJO_TOKEN` | Forgejo |
| `GATEWAY_SERVICE_TOKEN` / `GATEWAY_SERVICE_TENANT` | shared service token for the workspace-extension's sandbox RPCs |
| `IMAGE_REGISTRY_HOST` | registry host (default `git.agent.svc.cluster.local`) |
| `IMAGE_REGISTRY_SCHEME` | registry scheme (default `http`; the in-cluster registry is plaintext) |
| `TOOLCHAIN_ORG` | default owner `ListOCIImages` browses (default `agent-toolchain`) |
| `DEFAULT_BASE_IMAGE` | base image used when `CreateSandbox` omits one |
| `DERIVE_REPO` | repo for derived sandbox images (default `root/sandbox`) |
| `WORKER_BIN` | agent-worker binary injected into derived images |
| `BUILDKIT_ADDR` | buildkitd address for `BuildSandboxImage` + derive |
| `WORKSPACE_RUNTIME` | optional JSON overriding KVM/GPU device names + KVM security context |
| `SANDBOX_IDLE_TTL` | reclaim sandboxes idle this long (default `24h`; `0` disables) |
| `SANDBOX_REAP_INTERVAL` | reaper sweep period (default `10m`) |
| `NO_PROXY` / `no_proxy` | MUST include `.svc.cluster.local` (and the node edge IP) |
